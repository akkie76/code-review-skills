# Code Review Skills v1.0.0

[日本語](v1.0.0.ja.md)

Code Review Skills v1.0.0 is the first stable release of the evidence-driven
review workflow for Codex and Claude Code. It provides a documented, stable
finding-output contract while leaving review decisions dependent on the model,
available tools, and project context.

## What is stable

The public contract covers the `ACTION(Viewpoint):` finding-title format, the
documented action levels and viewpoints, and the required location, evidence,
trigger, impact, and direction for actionable findings. See the
[versioning policy](../VERSIONING.md) for the complete contract and compatibility
rules.

Stable output format does not mean stable findings: this release does not
guarantee identical wording, finding counts, line ranges, or detection rates
across models, agent versions, projects, or repeated runs. It does not guarantee
that every defect will be found or that every finding will be correct.

## Highlights since v0.1.0-beta.2

- The review workflow and output contract now require checking supporting
  claims, including claims in questions, summaries, and qualified statements,
  while avoiding findings for accurate, non-actionable scope notes.
- Guidance clarifies when to report new violations of mandatory repository
  rules, setup instructions that prevent startup, change-created dead helpers,
  and behavior-specific test gaps.
- An opt-in local evaluation runner supports Codex and Claude Code, with
  isolated revision snapshots and recorded invocation evidence. A separate
  human-adjudicated scoring workflow uses a per-agent 80-point threshold.
- The README, installation guides, release checklist, support policy, and
  security reporting instructions now describe the stable release.

## Evaluation evidence and accepted deviations

The [v2 evaluation report](../../tests/results/2026-10-08-issue-24-v2-evaluation.md)
records 27/29 strict primary passes for Codex and 26/29 for Claude Code, both
above the agreed 80% threshold. The campaign used 29 synthetic primary fixtures
and six diagnostic repeats per agent; Claude runs were reused from the original
campaign while Codex runs were replaced after a timeout. Scoring was
maintainer-adjudicated with assistant-assisted analysis, and the agents used
different permission and isolation configurations. These results are not a
measure of production review accuracy, nor do they establish that the Skill
caused the outcomes.

The strict mismatches remain visible in the report and are not reclassified as
passes:

- Codex used `MUST(Style)` instead of the expected `NITS(Style)` for a minor
  project-style issue, and omitted the required `BETTER(Simplicity)` finding
  while offering a valid test suggestion.
- Claude Code used `MUST(Test)` instead of `SHOULD(Test)` for an ineffective
  regression test. It also included unsupported or inaccurate supporting
  details in two cases, and one repeat used an imprecise location for a dead
  helper.

The maintainer accepted these deviations for this release because the required
core defects were detected and both agents exceeded the pre-agreed threshold;
the strict scorer still records each mismatch as a failure. The evaluation
report preserves the case-level rationale and counts. Future changes to review
behavior should be evaluated against the fixtures and their limitations rather
than inferred from this score alone.

## Installation and upgrade

Install the complete package from the `v1.0.0` tag using the
[installation guide](../INSTALLATION.md). If upgrading, replace the complete
installed package rather than copying only `SKILL.md`, then confirm that its
version marker reads `<!-- skill-version: v1.0.0 -->`.
