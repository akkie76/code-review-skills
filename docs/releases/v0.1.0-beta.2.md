# Code Review Skills v0.1.0-beta.2

[日本語](v0.1.0-beta.2.ja.md)

This beta improves the evidence available for evaluating the Skill and makes
installed package versions easier to identify. It also clarifies when the
Skill should be selected if a repository already contains review guidance.

## Highlights

- Ten new negative and realistic behavioral fixtures bring the suite to 28
  cases. The new cases include mixed-noise changes in Go, Java, and Python, a
  larger multi-file Python change, and traps for unsupported findings.
- CI applies fixture patches and checks Java 17, Go 1.22, and Python 3.11
  sources. The fixture validator checks case structure; it does not run an AI
  reviewer or establish review accuracy.
- Both generated packages expose `v0.1.0-beta.2` in a `skill-version` comment.
  The new [versioning policy](../VERSIONING.md) documents the output contract
  and distinguishes format compatibility from changes in review decisions.
- The Skill description now says repository instructions such as `AGENTS.md`
  and `CLAUDE.md` complement its workflow rather than replace it. The README
  documents explicit `/evidence-code-review` invocation when Claude Code's
  automatic selection varies.
- Both READMEs link to the publisher's page for
  [*コードレビューの教科書*](https://gihyo.jp/book/2026/978-4-297-15768-5), whose
  ideas informed this independently authored Skill. The Skill does not
  reproduce or replace the book.

## Evaluation evidence and limits

The [Codex sample from 2026-10-01](../../tests/results/2026-10-01.md) matched
fixture expectations in 12/12 single runs on selected cases, not all 28.
The [Claude Code sample from 2026-10-02](../../tests/results/2026-10-02.md)
matched fixture expectations in 7/7 runs, but the Skill was invoked in only
five; the other two matches were unassisted. These samples predate the final
Skill-description change and do not establish a general accuracy rate.

On the final release branch, a [2026-10-04 Codex sample](../../tests/results/2026-10-04.md)
matched fixture expectations in seven fresh sessions across five selected
cases, with successful Skill-file reads in all seven. Two cases were tested in
both English and Japanese. This was a maintainer-scored sample, not an
all-fixture or repeated-run evaluation.

A later [2026-10-04 Claude Code release-candidate evaluation](../../tests/results/2026-10-04-claude.md)
ran all 28 fixtures plus one Japanese repeat of a negative case. The Skill was
invoked in all 29 runs; exact fixture expectations passed in 27/29. Both
failures were prefix disagreements despite the required findings being present.
One run also contained an unsupported supporting behavior claim. These results
do not satisfy the all-fixture passing release gate or establish an accuracy
rate.

For that description change, the [#34 comparison](https://github.com/akkie76/code-review-skills/issues/34#issuecomment-5970330546)
reported that Claude Code matched expected invocation in 12/15 runs with the
old wording and 15/15 with the new wording, including 0/3 to 3/3 on the
previously missed review case. A separate 30-run Codex comparison recorded
successful Skill-file reads on review prompts in 9/9 runs for each wording;
it did not grade review quality. A read on a non-review prompt may be mere
inspection, not proof that the Skill changed the task. Each condition had only
three runs, and these results are model- and context-dependent.

Both Claude Code evaluations contained an unverified supporting claim, tracked
in [#35](https://github.com/akkie76/code-review-skills/issues/35).
The output contract already forbids unsupported factual details; this beta
does not claim that the observed tendency has been resolved. Fresh-session
all-fixture passing with both agents remains a release checklist item;
fixture-structure checks alone do not satisfy it.

## Compatibility and support

This release does not intentionally change the documented finding-prefix
syntax or required finding information. Review decisions can still vary by
model, agent, tools, and repository context. As a pre-1.0 beta, it does not
promise a stable output format or identical findings across runs. Read the
[support policy](../../SUPPORT.md) before reporting an issue; pull requests
require prior agreement.
