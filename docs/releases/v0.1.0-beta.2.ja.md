# Code Review Skills v0.1.0-beta.2

[English](v0.1.0-beta.2.md)

このベータ版では、Skillを評価するための根拠を増やし、インストールしたpackageの
バージョンを識別しやすくしました。また、リポジトリ内に既存のレビュー指示がある
場合のSkill選択を明確にしました。

## 主な変更

- 負例と現実的な行動評価fixtureを10件追加し、計28件にしました。Go・Java・Pythonの
  混在差分、複数ファイルにまたがる大きめのPython差分、根拠のない指摘を誘う負例を
  含みます。
- CIでfixtureの差分を適用し、Java 17、Go 1.22、Python 3.11のソースを検査します。
  fixture validatorが確認するのはcaseの構造であり、AIレビュアーを実行したり、
  レビュー精度を証明したりするものではありません。
- 両生成packageに`skill-version`コメントで`v0.1.0-beta.2`を示しました。新しい
  [バージョン方針](../VERSIONING.ja.md)では、出力契約と、形式上の互換性と
  指摘内容の変化の違いを説明しています。
- `AGENTS.md`や`CLAUDE.md`などのリポジトリ指示はSkillの代替ではなく、
  ワークフロー内で適用することをdescriptionで明確にしました。Claude Codeの
  自動選択が変動する場合は`/evidence-code-review`で明示的に呼び出せます。
- 両READMEに、Skillの着想元である
  [『コードレビューの教科書』](https://gihyo.jp/book/2026/978-4-297-15768-5)の
  出版社公式ページを追加しました。Skillは独自に作成したもので、書籍の内容を
  再現・代替するものではありません。

## 評価結果と制約

[2026-10-01のCodex評価](../../tests/results/2026-10-01.ja.md)では、選択したcaseの
単発実行12/12件がfixtureの期待に一致しました。全28件の評価ではありません。
[2026-10-02のClaude Code評価](../../tests/results/2026-10-02.ja.md)では7/7件が
fixtureの期待に一致しましたが、Skillが呼び出されたのは5件で、残り2件は
Skillなしの結果でした。いずれも最終的なdescription変更より前の部分的な評価で、
一般的な精度を示すものではありません。

最終的なリリースブランチでの[2026-10-04のCodex部分評価](../../tests/results/2026-10-04.ja.md)では、
選択した5件のcaseを新規sessionで計7回実行し、すべてfixtureの期待値に一致しました。
7回ともSkillファイルの読み込みが確認され、2件は英日両方で評価しました。
メンテナーによる採点であり、全件評価や反復評価ではありません。
追加のトークンを抑えたCodex評価では、`MUST(Document)`の期待とSkill利用を
確認しました。別のコード実行のcaseも出力の期待には一致しましたが、取得した
実行記録でSkillファイルの読み込みを確認できなかったため、Skillの合格には
数えません。いずれも全fixtureの評価にはなりません。

その後の[2026-10-04のClaude Codeリリース候補評価](../../tests/results/2026-10-04-claude.ja.md)では、
全28件のfixtureと追加の日本語負例1回を実行しました。29回すべてでSkillが
呼び出され、fixtureの厳密な期待には27/29回で合格しました。不合格の2件は
必須の指摘内容が存在する状態でのprefix不一致です。さらに、1回の実行には
根拠を確認できない挙動の補足が含まれました。一般的な精度を示すものでは
ありません。betaのリリース判断では、これらの逸脱を厳密な合格に読み替えず、
明示的に評価する必要があります。

description変更については、[#34の比較](https://github.com/akkie76/code-review-skills/issues/34#issuecomment-5970330546)で、
Claude Codeの期待どおりの呼び出しが旧文言の12/15回から新文言の15/15回に
なりました。従来呼び出されなかったレビューcaseは0/3回から3/3回でした。
Codexの別の30回比較では、レビュー依頼時のSkillファイル読み込みは両文言とも
9/9回でしたが、レビュー品質は採点していません。非レビュー依頼での読み込みも、
Skillが実際の作業を変えた証拠とは限りません。各条件は3回のみで、モデルや
文脈によって結果が変わり得ます。

両方のClaude Code評価には、確認していない補足の事実も含まれました
（[#35](https://github.com/akkie76/code-review-skills/issues/35)）。出力契約は
根拠のない記述を既に禁止していますが、この傾向が解消したとは主張しません。
betaのリリースチェックリストでは、両エージェントで新規sessionの抽出評価を
記録し、観測した逸脱をリスクに基づいて判断します。fixtureの構造検査だけでは
代替できません。

## 互換性とサポート

文書化した指摘プレフィックスや必須情報を意図的に変更していません。ただし指摘の
判断はモデル、エージェント、利用可能なツール、リポジトリの文脈によって変わります。
1.0前のベータ版のため、安定した出力形式や毎回同じ指摘を保証しません。
Issueの報告前に[サポート方針](../../SUPPORT.ja.md)を確認してください。
Pull Requestには事前の合意が必要です。
