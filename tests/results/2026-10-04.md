# Codex beta.2 release-candidate sample: 2026-10-04

[日本語](2026-10-04.ja.md)

## Scope and method

- Evaluator: the Skill maintainer's Codex assistant, manually comparing final
  outputs with fixed `case.json` expectations. This was not blind or
  independently graded.
- Source: `release/v0.1.0-beta.2` at `bdddfc7`; generated Codex Skill
  `v0.1.0-beta.2` installed at project scope in each temporary repository.
- Agent: Codex CLI `0.158.0-alpha.2.1`, model `gpt-6-luna`, high reasoning
  effort. Each request used a fresh, ephemeral, read-only session with user
  configuration ignored.
- Each repository started from the case's `repository/` files and installed
  Skill, committed as a baseline. `change.diff` was then applied to the
  working tree, with intent-to-add for new files. Requests came unchanged
  from `case.json`; no expected-result hints were added.
- A successful command reading the project-scoped `SKILL.md` was observed in
  the JSON event stream for every run. This is evidence of a Skill-file read,
  not a separate explicit Skill-tool invocation event. Final review content
  was scored independently against `must_report`, `must_not_report`,
  `prefixes`, and `output`.

## Limits and follow-up

- This is five of 28 fixtures, with one run per case/language pair. It does
  **not** satisfy the release checklist's all-fixture Codex item or establish
  a reliability or false-positive rate.
- Two cases were requested in both English and Japanese; this supports
  equivalent decisions for those cases only, not the full suite.
- Raw JSON event streams and outputs remain outside the repository. The
  evaluator knew the expectations and did not use an independent grader.
- Claude Code was not evaluated in this run; its separate release-checklist
  steps remain open.
